# THE HAILUO H3 VENV'S KNOWN-GOOD SET (minimax-h3-mlx/.venv) - 4.19.5.
#
# Every install into the H3 venv passes this file with -c, through ONE script:
# scripts/pinokio/h3_deps.sh. install_h3.js runs it (Install, "Repair Hailuo
# H3", "Update Hailuo H3 runner"), every Update runs it (scripts/post_update.sh
# 8b) and so does the panel's own Repair (POST /h3/repair). A constraint never
# installs anything by itself; it only forbids a resolve from leaving these
# versions - and uv MOVES a package that already sits outside them, so the same
# run that installs also repairs a drifted venv. scripts/check_post_update.js
# fails the build on an install into the H3 venv that does not go through
# h3_deps.sh, and on an eager --upgrade.
#
# WHY (4.19.5). Through 4.19.4 this venv was resolved from the runner's
# requirements.txt alone, and those lines are floors (mlx>=0.32.0,
# transformers>=4.57, huggingface_hub>=0.30, mlx-vlm>=0.4.4). Every new H3
# install got whatever PyPI held that day: on 2026-10-14 that was mlx 0.32.3,
# a day later mlx 0.32.4. The LTX venv's version of that story is 4.19.4 -
# tokenizers 0.23.3 shipped and every render on an updated install failed until
# the venv was put back. The next upstream release that breaks the H3 runner
# would have reached every new H3 install the same way, with no Phosphene
# release, no gate and no way back.
#
# HOW IT WAS CAPTURED. `uv pip freeze` of the H3 venv a from-zero 4.19.4
# install built on 2026-10-15 (Pinokio 8.2.0 environment, H3 engine pin
# 3f6c75c), minus pip / setuptools / wheel (the venv's --seed, not the
# resolve). Validated on 4.19.5 by real H3 renders: Draft t2v, i2v and
# Keyframes from zero, and identical output to the 4.19.4 venv for the same
# job and seed.
#
# NOT THE LTX VENV'S SET, ON PURPOSE. The two engines keep separate venvs
# because they disagree about MLX: LTX holds mlx==0.31.1
# (engine_constraints.txt; 0.32.x raises LTX's active memory - CLAUDE.md
# section 4, the "mlx 0.32 held" measurements), while the H3 runner needs
# mlx>=0.32 (on 0.31 it dies with "seed(): incompatible function arguments" -
# H3_MLX_MIN in mlx_ltx_panel.py) and mlx-vlm 0.7.8 needs mlx>=0.32.3. The
# 0.32 cache sweep on H3 was refuted (H3's peak is its weights), so the reason
# LTX holds 0.31.1 does not apply here. Shared packages that agree with the LTX
# venv: numpy 2.4.6, pillow 12.3.0, safetensors 0.8.0. Different by design:
# mlx (0.31.1 there), mlx-vlm (0.4.4 there), transformers (<5.13 there),
# tokenizers (0.22.x there), huggingface-hub (1.x there).
#
# Moving it: regenerate the WHOLE file from a from-zero install's venv, then a
# from-zero install + H3 renders on the new set. Change the engine pin
# (scripts/pinokio/h3_checkout.sh) and this file in the same commit when the
# runner's requirements.txt changes.
