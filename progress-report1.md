## 3. Feature architecture (as committed in `768faed` + staged fixes)

- **`shot_presets.py`** — two shot-list presets (default, and `EXTENDED_PRESET` = 15 shots) with pose/framing/expression/background text per shot (e.g. `close_front`, `close_three_quarter`, `chest_front`, `chest_profile_left/right`, `waist_*`, `fullbody_*`).
- **`character_sheet.py`** (592 lines) — the generation core. Builds prompts per shot (`_shot_prompt`, takes wardrobe + `identity_lock` + `style`), drives HiDream generation. Key detail: **`anchor_png` is set once from the first shot's output and reused as a fixed second reference image (K=2 edit mode) for every subsequent shot in the run** — a single fixed anchor, not a rolling chain. This is the current #1 suspect for a generation-quality issue (§5).
- **`hidream_engine.py`** (299 lines) — subprocess wrapper around the HiDream-O1 MLX CLI script. Directory search order for the model lab: `$HIDREAM_LAB_DIR` env → `~/HIDREAM-O1-MLX-LAB-active` → `~/AI/HIDREAM-O1-MLX-LAB-active` → `~/AI/projects/HIDREAM-O1-MLX-LAB-active` → `/Volumes/AI/HIDREAM-O1-MLX-LAB-active` → fallback. Returns a list of dicts per generated image: `png_path`/`seed`/`engine`/`width`/`height`.
- **`sheet_jobs.py`** — async job queue, **in-process `threading.Thread` + in-memory `_JOBS` dict, not persistent**, single `_SHEET_LOCK` in `character_sheet.py`. This is why any future MCP server (or any second process) MUST be a thin HTTP client of the running Flask app, never import these modules directly — a second process would get its own independent lock/registry and reintroduce GPU-contention races. Status strings are `"completed"` / `"failed"` (not `"done"`).
- **`routes/phosphene.py`** — 11 routes, including settings-panel endpoints (start job, poll status, reroll a single shot, serve a shot's thumbnail), plus the pre-existing draft-character/face-to-turnaround proxy routes.
- **`static/phosphene-sheet.js`** — frontend: settings panel, shot grid, polling loop, reroll buttons, per-shot "copy prompt" button (built earlier, already satisfies the "make prompt clickable to copy" request — confirmed by user, no new work needed there).
- **`HIDREAM_SETUP.md`** — setup doc: HiDream-O1 is Apple-Silicon-Mac-only (MLX/Metal), cannot run on Windows/Linux. Covers where to get the model (`mlx-community/HiDream-O1-Image-Dev-mlx-bf16` on Hugging Face), install steps, `HIDREAM_LAB_DIR` layout, and how to verify via `GET /api/phosphene/status`.
- **`RING_VIZ_MCP.md`** — discussion-only doc (not implementation) inventorying all 35 routes/6 blueprints and what would need to change to expose Ring Visualizer as an MCP server (headline requirement: thin HTTP client architecture, per the job-queue note above).

5. **Ring thumbnails disappearing during sidebar resize (iPad) — FOUND, FIXED, staged (2026-09-03).** User reported thumbnails vanishing while dragging the resize handle between the ring/stage area and the right sidebar, on the iPad (fullscreen/standalone PWA over Tailscale).

11. **PNG-validity check added to `hidream_engine.generate_hidream()` -- FIXED, tested, staged (2026-09-03, later same day).** User reported a corrupted result from a reroll: a "black" thumbnail whose actual PNG file only had real pixel data for roughly the top eighth of the frame, the rest black -- the classic signature of a write that was interrupted partway through, not a bad *generation* (which would still be full-height, just wrong-looking).
